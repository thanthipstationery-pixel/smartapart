# เอกสารข้อกำหนดและการออกแบบระบบ (Design Specification)
## ระบบจัดการข้อมูลผู้เช่าเพิ่มเติม & ระบบย้ายห้องพักอัตโนมัติ (Tenant Management & Room Transfer)

**วันที่**: 29 กรกฎาคม 2569  
**สถานะ**: อนุมัติการออกแบบ (Approved)  
**ระบบเป้าหมาย**: `SmartApart` (Next.js 16 + Prisma + SQLite)

---

## 1. ภาพรวมและวัตถุประสงค์ (Overview & Goals)

เอกสารนี้ครอบคลุมการพัฒนาและปรับปรุงระบบจัดการข้อมูลผู้เช่าและห้องพัก 3 ฟีเจอร์หลัก ตามความต้องการของเจ้าหน้าที่อพาร์ทเมนท์:

1. **ฟีเจอร์ "ยกเลิกการเข้าพัก"**: สำหรับลบข้อมูลผู้เช่าทดลอง หรือรายการเข้าพักที่คีย์ผิดพลาด โดยระบบจะทำการลบข้อมูลผู้เช่า, บิลแรกเข้า, และประวัติมิเตอร์น้ำไฟเริ่มต้นออกอย่างถาวร พร้อมคืนสถานะห้องพักเป็น **"ว่าง (VACANT)"** 100%
2. **ฟีเจอร์ "แก้ไขวันที่เริ่มสัญญาเช่า"**: เพิ่มช่องระบุ `วันที่เริ่มสัญญาเช่า (startDate)` ในหน้าต่างแก้ไขข้อมูลผู้เช่า (`EditTenantModal`) เพื่อให้เจ้าหน้าที่ปรับแก้ไขวันที่เริ่มสัญญาเช่าให้ถูกต้องได้
3. **ฟีเจอร์ "ระบบย้ายห้องพักอัตโนมัติ (Automated Room Transfer)"**: สร้างหน้าต่างคำสั่งย้ายห้องพัก (`RoomTransferModal`) แบบ 1-Click ช่วยโอนย้ายผู้เช่าจากห้องเดิมไปยังห้องใหม่ที่เป็นห้องว่าง, จดมิเตอร์น้ำ-ไฟวันย้ายออกจากห้องเดิม, จดมิเตอร์น้ำ-ไฟเริ่มต้นห้องใหม่, โอนย้ายมัดจำประกันสัญญา และสลับสถานะห้องเดิมเป็น "ว่าง" และห้องใหม่เป็น "มีผู้เช่า" อัตโนมัติ

## 3. รายละเอียดการทำงานของแต่ละฟีเจอร์ (Detailed Workflows)

### ฟีเจอร์ที่ 1: ยกเลิกการเข้าพัก (`ยกเลิกการเข้าพัก`)
- **ปุ่มเปิดใช้งาน**: ปุ่ม `🗑️ ยกเลิกการเข้าพัก` ใน `RoomModal` หรือ `EditTenantModal`
- **การแจ้งเตือนยืนยัน**: ขึ้น Dialog ยืนยัน: *"คุณต้องการยกเลิกการเข้าพักนี้ใช่หรือไม่? ข้อมูลผู้เช่า บิลแรกเข้า และมิเตอร์จะถูกลบออก และห้องจะกลับเป็นสถานะ 'ว่าง'"*
- **API Endpoint**: `DELETE /api/tenants/[id]`
  - ลบประวัติการชำระเงิน `Payment` ที่เกี่ยวข้องกับบิลแรกเข้า
  - ลบบิลแรกเข้า `Invoice`
  - ลบประวัติมิเตอร์น้ำไฟ `MeterReading` ที่ถูกจดไว้ตอนเข้าพัก
  - ลบข้อมูลผู้เช่า `Tenant`
  - ปรับสถานะห้องพัก `Room.status` กลับเป็น `VACANT` (ห้องว่าง)

### ฟีเจอร์ที่ 2: แก้ไขวันที่เริ่มสัญญาเช่า (`แก้ไขวันที่เริ่มสัญญาเช่า`)
- **องค์ประกอบ UI**: ตัวเลือกวันที่ `<input type="date">` ผูกกับตัวแปร `editTenantStartDate`
- **API Endpoint**: `PUT /api/tenants/[id]`
  - รับค่า `startDate` จาก Request Body
  - ทำการอัปเดตฟิลด์ `Tenant.startDate` ในฐานข้อมูล

### ฟีเจอร์ที่ 3: ระบบย้ายห้องพักอัตโนมัติ (`ระบบย้ายห้องพักอัตโนมัติ`)
- **ปุ่มเปิดใช้งาน**: ปุ่ม `🔄 ย้ายห้องพัก` ใน `RoomModal`
- **ข้อมูลที่ต้องกรอกใน Modal (`RoomTransferModal`)**:
  - `targetRoomId`: เลือกห้องพักปลายทาง (กรองเฉพาะห้องที่มีสถานะ `VACANT` เท่านั้น)
  - `sourceWaterMeter`, `sourceElecMeter`: เลขมิเตอร์น้ำ-ไฟ วันย้ายออกจากห้องเดิม
  - `targetWaterMeter`, `targetElecMeter`: เลขมิเตอร์น้ำ-ไฟ เริ่มต้นของห้องใหม่
  - `transferDate`: วันที่ทำรายการย้ายห้อง (ค่าเริ่มต้นคือวันที่ปัจจุบัน)
  - `note`: หมายเหตุเพิ่มเติม (ถ้ามี)
- **API Endpoint**: `POST /api/tenants/[id]/transfer`
  - การทำงานแบบ Atomic Transaction:
    1. บันทึกมิเตอร์สุดท้ายของห้องเดิม `MeterReading` (`recordedBy: 'ROOM_TRANSFER_OUT'`)
    2. บันทึกมิเตอร์เริ่มต้นของห้องใหม่ `MeterReading` (`recordedBy: 'ROOM_TRANSFER_IN'`)
    3. ปรับสถานะห้องเดิม `Room.status = 'VACANT'`
    4. ปรับสถานะห้องใหม่ `Room.status = 'OCCUPIED'`
    5. อัปเดตข้อมูลผู้เช่า `Tenant.roomId = targetRoomId` พร้อมบันทึกประวัติการย้ายลงใน `Tenant.note`

## 4. ข้อกำหนด API Endpoints

### Endpoint 1: `DELETE /api/tenants/[id]`
- **Method**: `DELETE`
- **Path**: `/api/tenants/[id]`
- **หน้าที่**: ลบข้อมูลการเข้าพักอย่างถาวร และคืนสถานะห้องเป็น `VACANT`

### Endpoint 2: `POST /api/tenants/[id]/transfer`
- **Method**: `POST`
- **Path**: `/api/tenants/[id]/transfer`
- **Body Data Format**:
  ```json
  {
    "targetRoomId": "string",
    "sourceWaterMeter": 120.0,
    "sourceElecMeter": 450.0,
    "targetWaterMeter": 5.0,
    "targetElecMeter": 10.0,
    "transferDate": "2026-07-29",
    "note": "ย้ายห้องจาก D3 ไป A5"
  }
  ```
- **หน้าที่**: ดำเนินการย้ายห้องพัก สลับสถานะห้อง และบันทึกมิเตอร์น้ำไฟทั้งสองห้อง
